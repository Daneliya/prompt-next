# Prompt Next V0.2.8 开发文档

应用版本为 `0.2.8`，对应 Git 标签 `v0.2.8`。本文记录从 0.2.7 到 0.2.8 的问题、改法、代码位置、验收方法和发布边界。环境安装与日常开发另见 [开发文档](开发文档.md) 和 [开发教程](开发教程.md)。

## 1. 性能与架构

### 1.1 写入后局部刷新

此前多种写操作都调用同一个 `reload()`，重新获取全库提示词、作者及存储统计。统计会遍历图片和视频目录，因此收藏一条提示词也可能触发附件扫描。

| 场景 | 0.2.8 的处理 |
| --- | --- |
| 新建、编辑 | Go 保存成功后返回完整条目。Vue 根据 ID 插入或替换该条目，再恢复列表排序。保存时遇到当前作者目录没有的名称，才补读作者列表。 |
| 单条或批量收藏 | 等数据库写入成功，再更新本地相应条目的收藏标记。 |
| 删除到回收站 | 删除成功后从本地列表移除这些 ID，刷新当前详情选择。可恢复附件仍留在磁盘，继续计入磁盘占用。 |
| 批量改分类、从回收站恢复 | 使用 `PromptsByIDs` 读取指定 ID 的实际结果，包括数据库写入的更新时间。恢复条目后也刷新作者目录。 |
| 分类或标签改名 | 使用 `ListPromptsByKind` 重读对应库，再替换这部分内存数据。标签改名在数据库端先按库和标签过滤，再反序列化符合条件的记录。 |
| 彻底删除、清理附件 | 更新回收站或清理结果，标记存储统计失效。 |
| 启动、JSON 导入 | 全量读取提示词和作者，供作者跨库聚合、合集和本地搜索使用。 |

`replacePrompts` 通过替换数组与变更条目对象触发界面更新。针对 ID 的读取使用主键定位，按库读取复用现有库类型索引。列表虚拟化限制前端渲染量，启动时的全库 JSON 反序列化仍存在。

代码见 [App.vue](../frontend/src/App.vue)、[service.go](../internal/library/service.go)、[store.go](../internal/library/store.go) 和 [collection.go](../internal/library/collection.go)。

### 1.2 工作台统计与附件缓存

- 工作台可见或设置打开「数据管理」时才请求统计。页面隐藏期间只记录统计已失效，下次进入时补读。
- `StorageSnapshot(false)` 读取数据库文件占用和近 14 天新增数据。Vue 保留上一次的图片、视频大小和数量。首次统计，或新增附件、彻底删除、清理附件、导入之后，才用 `StorageSnapshot(true)` 遍历媒体目录。
- 普通文字编辑、收藏、图片重排只更新基础统计。编辑时按附件名称集合判断是否有新增文件，移动效果图与参考图的位置也不会仅因顺序变化而重扫。
- 一个统计请求正在进行时，后续请求共用该请求。期间若有新变更且统计页仍可见，读取完成后补刷最新状态。该缓存随应用会话保存。

代码见 [useStorageStats.ts](../frontend/src/composables/useStorageStats.ts) 和 [stats.go](../internal/library/stats.go)。

### 1.3 实时搜索和大库浏览

| 原问题 | 0.2.8 的处理 |
| --- | --- |
| 必须点击「搜索」才应用输入 | 主库与作者主页分开保存输入值。输入停顿约 160 ms 后应用，回车或点击「搜索」立即应用，清空立即恢复。 |
| 每次搜索都要重复转换整库文字 | 每个条目的小写搜索字段按对象缓存。搜索覆盖标题、中英文正文、说明、编号、原作者、来源网址、标签、分类、负向词、参数和模型。局部更新替换变更对象后，该条目的缓存会重新生成。 |
| 三种视图都渲染全部结果 | 列表用 Naive UI 的 `NVirtualList` 渲染可见行，并测量可变行高。卡片和瀑布流按页显示，每页最多 72 条。 |
| 翻页和多选容易混淆 | 「全选当前结果」覆盖当前筛选结果，包括其他页。切换查询、排序、分类或视图时回到开头。作者页返回原库时恢复进入前的页码或滚动位置。 |

搜索目前仍在内存中匹配。卡片和瀑布流的分页控制的是界面渲染量。数据库分页、FTS5 和拼音检索列入后续优化。

代码见 [useDebouncedQuery.ts](../frontend/src/composables/useDebouncedQuery.ts)、[usePromptFilters.ts](../frontend/src/composables/usePromptFilters.ts)、[PromptResults.vue](../frontend/src/components/PromptResults.vue) 和 [PromptRow.vue](../frontend/src/components/PromptRow.vue)。

### 1.4 瀑布流封面与滚动条

原来图片完成加载后才设置宽高比，视频也可能在生成预览后改变画幅。窗口尺寸接近滚动条显示阈值时，卡片宽度、换列和滚动高度容易互相影响。

1. 进入瀑布流或翻页时，`CoverDimensions` 批量读取当前页绘画封面的图片头并返回宽高比。读数期间显示骨架屏，挂载卡片后沿用这个比例。
2. 宽高比按条目编号与文件名缓存。读不到尺寸时使用稳定的默认比例。视频封面在当前页挂载前并发读取首段视频的元数据，按原画幅预排。读不到尺寸时使用 16:9，预览图或后备视频帧加载后保持预排尺寸。
3. 瀑布流滚动区用 `scrollbar-gutter: stable` 预留滚动条位置。悬停用 `transform` 放大图片，封面用圆角裁切限制放大范围，信息层使用绝对定位。绘画和视频使用同一套渐变信息层。卡片间距由条目容器的底部内边距提供，避免分栏时各列第一张卡片错位。开启「减少动态效果」后取消封面放大动画。

代码见 [images.go](../internal/library/images.go)、[PromptResults.vue](../frontend/src/components/PromptResults.vue)、[VideoCover.vue](../frontend/src/components/VideoCover.vue) 和 [workspace.css](../frontend/src/workspace.css)。

## 2. 作者、作品来源和数据兼容

### 2.1 作者目录与作者主页

- 左栏「所有作者」展示收录作者数、作品最多的作者、近 30 天活跃作者和未署名条目数。可搜索显示名称、原作者名称和简介，按作品数、最近活跃或名称排序，并从实际作品链接筛选来源。卡片和列表显示各库作品分布和最近活跃日期，卡片另展示最多三条媒体作品预览。
- 条目详情里的原作者可打开作者主页。卡片和列表可在「展示字段」勾选「原作者」。作者页默认显示四个库的全部在库作品，支持按库筛选、搜索、排序和切换视图。回收站里的条目不计入在库数量。
- 早期按 URL 分组会把同一作者的不同作品拆开。现在以去掉首尾空白后的原作者名称分组，同名条目会归到一起。作者资料页编辑的是显示名称和简介，原作者名称仍作为稳定关联键。
- 无原作者名称的条目不建立作者资料，仍可保留提示词原链接。本版按同名合并，作者重名拆分、别名合并和跨平台账号关联尚未实现。

### 2.2 作品链接和离线站点图标

- 编辑表单把「原作者名称」与「提示词原链接」分开。原链接仍使用已有的 `authorUrl` 字段，旧库和备份中的链接可直接读取。
- 四个库统一在详情顶部的创建、更新时间下方显示紧凑入口，包含图标、域名和外链标识。卡片、列表、瀑布流和媒体缩略图上均不放原链接。
- 图标打包在应用内，浏览详情时直接读取本地资源。域名规则支持列出的站点及其子域名，未收录的网站显示域名首字母。内置覆盖 PromptHub、Civitai、LiblibAI、即梦、Midjourney、小红书、GitHub、Hugging Face、哔哩哔哩和抖音。Midjourney 使用本地帆船图标。
- 点击后调用桌面层打开系统浏览器。表单保存和打开链接都只接受有效的 HTTP 或 HTTPS 地址。

代码见 [PromptEditor.vue](../frontend/src/components/PromptEditor.vue)、[PromptSource.vue](../frontend/src/components/PromptSource.vue)、[站点图标映射](../frontend/src/promptSourceIcons.ts) 和 [图标资源目录](../frontend/public/icons/sites/)。

### 2.3 SQLite 迁移与备份

数据库 `user_version` 从 6 升到 7，业务表从 4 张增至 5 张。迁移在事务里执行，从现有在库条目回填作者，同名保留一条。以后写入提示词或修改原作者时，由 SQLite 触发器补建缺少的作者记录。条目的作品链接和附件路径沿用原有字段。

| `authors` 列 | 用途 |
| --- | --- |
| `source_name` | 原作者名称，主键。 |
| `name` | 用户可编辑的显示名称。 |
| `bio` | 用户可编辑的简介。 |

完整 JSON 备份导出 `authors`。合并导入保留本机已有的同名作者资料，覆盖恢复先生成安全快照，再恢复备份中的作者资料。旧备份缺少 `authors` 时保留本机作者资料，并从写入的作品补建缺少的作者。新备份使用 `prompt-next` 标识，本版也接受 `bigfish-prompt-manager`。需要回退到只支持 schema 6 的版本时，应使用升级前的数据目录副本或备份。

代码见 [authors.go](../internal/library/authors.go)、[store.go](../internal/library/store.go) 和 [backup.go](../internal/library/backup.go)。

## 4. 工程化与维护

- `App.vue` 保留页面路由、共享状态、跨库选择和保存编排。首页、编辑器、结果列表、条目行及设置外框已拆分。设置各分区的表单状态仍由 `App.vue` 管理。
- 主题主色由 `designTokens.ts` 统一提供，工作区 CSS 补充间距、圆角、状态色、阴影和抽屉层级变量。部分旧样式仍有独立色值。
- 英文界面的错误提示使用 `backendErrors.ts` 集中翻译常见 Go 校验错误和包装前缀，保留底层诊断。通用错误码协议仍未引入。
- 前端新增 ESLint 和 Vitest。测试覆盖搜索防抖与清空、常见错误翻译、站点域名匹配、隐藏页面的统计延迟和附件缓存，以及视频画幅读取与取消。Go 测试新增定向查询、封面尺寸和媒体统计检查，并覆盖作者迁移、四库同名作者备份恢复及来源链接保持。
- 三种语言的 README 都在首页图后补充绘画库卡片与瀑布流截图，并加入本版本文档入口。视频库、合集、作者页、设置和暗色模式的截图可随实机验收补录。

## 5. 验收步骤

### 自动检查

在项目根目录执行。

```bash
node build/version.mjs
wails3 task lint
wails3 task test
```

版本命令应输出 `0.2.8`。此前已通过 ESLint、四项 Vitest、TypeScript 构建、`go vet` 和 `go test`，也验证了 macOS ARM64 和 Windows x64 的生产编译。升版后已再次通过 Go 测试，并核对 macOS plist 和 Windows 版本资源的生成值。桌面操作和 GitHub 上的打包发布流程仍需按下表验收。

### 桌面操作

| 场景 | 复现步骤 | 预期结果 |
| --- | --- | --- |
| 旧库迁移 | 以旧数据库副本启动。准备同名作者在不同库的条目，给每条填写不同的作品链接。 | 出现一个作者档案，作者页能看到全部在库条目，每条详情仍打开各自的链接。 |
| 作者改名和备份 | 在作者页改显示名称并填写简介。导出完整备份，再在独立测试数据目录覆盖恢复。 | 关联条目仍在，显示名称和简介恢复，恢复前生成安全快照。 |
| 本地站点图标 | 断网打开有已收录域名及陌生域名链接的条目。 | 已收录站点图标可显示，陌生域名显示首字母。原链接只出现在详情顶部的小按钮里。 |
| 搜索、分页与多选 | 用超过 72 条的库输入关键词，接着清空，分别切换三种视图，再选「全选当前结果」。 | 搜索自动刷新，清空立即恢复。卡片和瀑布流可翻页，列表可连续滚动，批量选择覆盖筛选结果的所有页。 |
| 作者页返回 | 在卡片或列表设置筛选、翻页或滚动后，打开作者主页再返回。 | 保留原筛选及页码或滚动位置。 |
| 瀑布流抖动 | 在视频库瀑布流把窗口调到接近出现滚动条的宽高，反复悬停边缘卡片，并滚过新加载的封面。 | 滚动区宽度稳定，卡片悬停只影响封面和信息层，媒体加载保持卡片画幅。 |

| 窄窗口和键盘 | 将窗口缩到接近最小宽度，打开详情抽屉，使用 Tab 导航，再开启系统「减少动态效果」。 | 左侧图标和短文字可切库，抽屉可关闭，键盘焦点清晰，封面动效减弱。 |
| 英文、深色与图表 | 切换英文及深色主题。填写无效原链接后尝试保存，再悬停、点击图表。 | 常见校验错误显示英文，图例可读，圆心统计及锁定状态更新。 |
| 双平台标题栏 | 在 macOS 和 Windows 分别启动生产包，拖动窗口，操作最小化、最大化或缩放，再检查「关于」。 | 标题栏为单行，工具和快捷键可用，「关于」显示 0.2.8。 |

## 6. 打包与发布

`build/config.yml` 的 `info.version` 是版本源。应用「关于」、macOS plist、Windows 可执行文件版本资源和 NSIS 安装器读取这个版本。原 `prompt-manager` 构建名称已经替换，旧数据目录名称继续用于迁移识别。

| 平台 | 本地命令 | 产物 |
| --- | --- | --- |
| macOS Apple Silicon | `wails3 task darwin:package:dmg ARCH=arm64` | `bin/Prompt Next.dmg` |
| Windows x64 免安装版 | `wails3 task windows:build ARCH=amd64` | `bin/prompt-next.exe` |
| Windows x64 安装版 | `wails3 task windows:package ARCH=amd64` | `bin/Prompt-Next-amd64-installer.exe`，同时生成免安装版 |

源码提交后，在正确的提交上创建并推送版本标签。

```bash
git tag -a v0.2.8 -m "Prompt Next v0.2.8"
git push origin v0.2.8
```

[GitHub Actions 工作流](../.github/workflows/ci.yml) 分为三个阶段。

1. **Check** 在 macOS 上安装锁定依赖，执行 ESLint、Vitest、前端类型检查与构建、`go vet` 和 `go test`。
2. **Package** 在标签与应用版本一致时构建 macOS ARM64 DMG 和 Windows x64 两种 EXE，并上传构建产物。
3. **Release** 在两个平台打包成功后上传附件。首次运行创建草稿，已有同名 Release 则更新附件。维护者在 GitHub 核对三个附件及验收结果后发布。
